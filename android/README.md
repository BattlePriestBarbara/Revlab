# RevLab Mobile (Android client)

A one-Activity Android app: a WebView, an address bar, and no analysis code of
its own. It shows the RevLab dashboard that is running on the PC, because that
is where Ghidra, the USB-attached device and the workspaces live. Pointing the
phone at the desktop is the whole feature: findings, sessions and reports on a
second screen while the PC is busy decompiling.

## Build

```powershell
python android\build_apk.py
# or the wrapper, if you prefer a PowerShell entry point:
powershell -ExecutionPolicy Bypass -File android\build_apk.ps1
```

Output: `dist\RevLab-Mobile-0.2.0.apk`, signed with a development key so
`adb install` accepts it.

The build lives in `build_apk.py` rather than in PowerShell on purpose:
PowerShell 5.1 does not pass non-ASCII paths or `-Dname=value` arguments to
native programs intact, and this machine's user profile is under a non-ASCII
path, which made `aapt2` read the wrong `android.jar` path. Python hands Windows
the exact command line. The `d8`/`apksigner` batch files are bypassed for the
same reason: their jars are started directly.

The script needs a JDK (11+) and an Android SDK with command-line tools. It
installs the missing SDK parts itself (`platforms;android-34`,
`build-tools;34.0.0`, `platform-tools`) through `sdkmanager`, accepting the SDK
licences -- and falls back to downloading those exact packages from
`dl.google.com` when `sdkmanager` is not usable. No Gradle, no plugin
repository, no daemon: the four tools that do the work (`aapt2`, `javac`, `d8`,
`zipalign` + `apksigner`) ship in the SDK.

Useful flags:

| Flag | Meaning |
| --- | --- |
| `--sdk C:\path\to\Sdk` | Android SDK root (default: `%LOCALAPPDATA%\Android\Sdk`, `$env:ANDROID_HOME`) |
| `--java-home C:\path\to\jdk` | JDK used for `javac`, `d8`, `keytool`, `apksigner` |
| `--api 34` / `--build-tools 34.0.0` | platform and build-tools to build against |
| `--skip-install` | do not touch the SDK; fail if a component is missing |
| `--dry-run` | resolve the toolchain and stop |

## One source-shape constraint

R8 (`d8`) in this environment aborts with a `NullPointerException` on any class
file that carries an `InnerClasses` attribute -- nested or anonymous classes.
That was reproduced against build-tools 29.0.3 through 36.0.0 and JDK 16 and 25,
with and without debug info, on ASCII and non-ASCII paths, so the client simply
keeps to **one top-level class per file** (`MainActivity`, `ConnectListener`).
Classes that extend `Activity` or use `WebView` are fine; only the attribute is
fatal.

`python android\check_toolchain.py` measures this instead of asserting it:

```
  Plain          OK    (no library types, no nesting)
  PlainActivity  OK    (extends an android.jar class (library resolution required))
  Nested         FAIL  (contains an anonymous class (InnerClasses attribute))
```

`tests/test_packaging.py` fails the suite if nesting is reintroduced.

## Use

1. On the PC, start RevLab and press **共享给浏览器/手机** (share). The window
   prints two addresses and copies the phone one to the clipboard.
2. On the phone, open RevLab Mobile and paste it into the address bar:
   `http://192.168.1.5:8765/?t=<访问码>`. Press 连接.
3. The dashboard appears. The address is remembered for next time.

The `?t=` part is the access code RevLab generates for that session; without it
the server answers `401`. If the phone cannot reach the PC, check that both are
on the same network and that the PC's firewall allows the port that was printed
(the first bind usually raises a firewall prompt).

Cleartext HTTP is enabled in the manifest on purpose: the workbench is a LAN
service, not a public one. It is not reachable from the internet, and the code
above is the only credential.
